## 背景

当前 skill 名称校验过于严格，仅允许 `a-z 0-9 -`。你希望放开英文冒号 `:`，范围限定为**导入/扫描**（创建保持严格），冒号作为**通用分隔符**（与连字符同等对待，可有多个、不能首尾、不能连续或与连字符相邻）。

## 关键约束（代码层面已确认）

skill 名称会作为磁盘目录名。一旦含冒号的 skill 通过导入进入 hub，后续所有操作（读文件、同步、删除、导出）都会经过同一 `validate_skill_id`。因此"仅放开导入/扫描"实际意味着：**只有"新建（create）"这一个入口保持严格**，其余路径（导入、外部扫描、hub 扫描、读取、同步、删除、导出、归档导入/导出、frontmatter name）都必须放开，否则导入进来的 skill 会变成"看得见但无法操作"的幽灵条目。

冒号 `:` 在 Windows 文件系统是保留字符——含冒号的目录在 Windows 上无法创建。这是仅放开导入/扫描、保留创建严格的根本原因：导入的目录已存在于用户系统（必然在非 Windows 或合法环境），创建则可能直接失败。

## 实现方案

### 1. 后端：拆分校验函数（`src-tauri/src/skills/paths.rs`）

把 `validate_skill_id`（paths.rs:84）重构为两个层次：

```rust
// 允许 a-z 0-9，分隔符为 - 和 :（通用规则，导入/扫描/读取/同步/导出全部走这里）
pub(crate) fn validate_skill_id(skill_id: &str) -> Result<(), SkillManagerError> {
    validate_skill_id_with(skill_id, false)
}

// 创建专用：额外禁止冒号（Windows 目录名安全），仅 create_skill 调用
pub(crate) fn validate_creatable_skill_id(skill_id: &str) -> Result<(), SkillManagerError> {
    validate_skill_id_with(skill_id, true)
}

fn validate_skill_id_with(skill_id: &str, forbid_colon: bool) -> Result<(), SkillManagerError> {
    let valid_length = (1..=64).contains(&skill_id.len());
    let valid_characters = skill_id.bytes().all(|character| {
        character.is_ascii_lowercase()
            || character.is_ascii_digit()
            || character == b'-'
            || (!forbid_colon && character == b':')
    });
    // 首尾不能是分隔符，分隔符之间不能连续或相邻（--/::/-:/:- 均禁止）
    let separator = |c: u8| c == b'-' || (!forbid_colon && c == b':');
    let valid_edges =
        !skill_id.is_empty() && !separator(skill_id.as_bytes()[0]) && !skill(skill_id.as_bytes()[skill_id.len() - 1]);
    let valid_separators = skill_id
        .as_bytes()
        .windows(2)
        .all(|pair| !(separator(pair[0]) && separator(pair[1])));

    if valid_length && valid_characters && valid_edges && valid_separators {
        return Ok(());
    }
    Err(SkillManagerError::new("invalid_skill_id").with_param("skillId", skill_id))
}
```

（上面代码块中的 `skill(...)` 是笔误，实际应为 `separator(...)`；实现时写正确。）

### 2. 后端：创建路径切换到严格校验

`skill_create` 命令最终调用 `create_skill`（files.rs）。需要在该函数内把 `validate_skill_id` 换成 `validate_creatable_skill_id`。我会先读 files.rs 的 `create_skill` 函数确认具体调用点再改。

### 3. 后端：其余所有路径保持调用 `validate_skill_id`（无需改动）

`skill_root`、`scan_external_directory`、`scan_skill_directory`、`parse_frontmatter`、`import_external_skill`、`export_skill_archive`、`inspect_archive` 等全部沿用放开通用规则后的 `validate_skill_id`。这样含冒号的 skill 能完整地导入、扫描、读取、同步、删除、导出。

### 4. 前端：创建模态框保持严格正则（`SkillCreateModal.tsx:12`）

`SKILL_ID_PATTERN` 维持原样（不含冒号），确保创建入口与后端 `validate_creatable_skill_id` 一致：

```ts
const SKILL_ID_PATTERN = /^(?!-)(?!.*--)[a-z0-9]+(?:-[a-z0-9]+)*$/;
```

无需改动。

### 5. i18n 提示文案（`src/i18n/messages.ts`）

`skillNameHint` 是**创建**输入框下的提示，对应严格规则，**保持不变**（仍为"小写字母、数字和单个连字符"）。导入/扫描界面没有针对名称格式的常驻提示（扫描失败走 `externalScanError` 错误码），所以无需新增文案。

## 影响面小结

- 新建 skill：规则不变（无冒号），规避 Windows 目录创建失败。
- 导入外部 skill / 导入归档 / 外部目录扫描 / hub 扫描 / 读取编辑 / 同步 / 删除 / 导出：全部放开，含冒号的 skill 可正常流转。
- 冒号规则：通用分隔符，可有多个（`a:b:c`），禁止首尾、禁止连续或与连字符相邻（`::` `:-` `-:` 均禁）。

## 不在范围内

- 不放开创建入口的冒号限制。
- 不改动 frontmatter `name` 与目录名一致性校验逻辑（`skill_name_mismatch` 仍按原样比对）。
- 不为后端错误码新增 i18n 翻译（本次仅放宽字符规则，错误码体系不变）。
