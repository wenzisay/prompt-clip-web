## 目标
在 skill 详情页编辑文件有未保存修改时,点击左侧 Sidebar 的「Prompts」(或「Skills」)切换入口,弹出与"切换文件/返回列表"完全相同的确认框,确认后才切换;取消则留在原地。本次只做 skill 详情页(Prompts 侧脏状态机制缺失,留作后续)。

## 决策(已确认)
- 仅 skill 详情页拦截;Prompts 侧本次不动
- 复用 `SkillDetailPage` 既有的 `pendingAction` + `SkillConfirmModal` 守卫模式
- 确认框文案复用 `t.skills.unsavedChanges` / `t.skills.confirm`

## 核心机制
- `SkillDetailPage` 通过 `useImperativeHandle` + `forwardRef` 暴露一个 imperative 方法 `requestNavigateAway(onProceed: () => void)`,内部逻辑与现有 `back`/`selectEntry` 守卫完全一致(脏→`setConfirm`+`pendingAction`,确认后执行 `onProceed`;非脏→直接 `onProceed`)。
- `SkillManagerPage` 持有 `detailRef`,新增 `handleSelectSection(section)`:在 skill 详情页(`selectedSkillId` 非空)时调 `detailRef.current?.requestNavigateAway(() => setAppSection(section))`;否则直接 `setAppSection(section)`。传给 `<Sidebar>` 的 `onSelectSection`。
- `Sidebar` 新增可选 prop `onSelectSection?: (section: AppSection) => void`;`SectionButton` 的 `onSelect` 用 `onSelectSection ?? setAppSection`。
- **Prompts 侧无影响**:`PromptManagerPage` 渲染 `<Sidebar />` 不传 `onSelectSection`,回落到默认 `setAppSection`,行为不变。

## 改动清单

### 1. `src/components/skill/SkillDetailPage.tsx`
- 改为 `forwardRef` + 定义 `SkillDetailPageHandle = { requestNavigateAway: (onProceed: () => void) => void }`。
- 抽取现有守卫逻辑为内部 helper `guardAction(proceed: () => void)`(复用 `isDirty`/`pendingAction`/`setConfirm`),让 `selectEntry`/`back`/`requestNavigateAway` 都调它(DRY,消除现有重复块)。
- `useImperativeHandle(ref, ...)` 暴露 `requestNavigateAway(onProceed)` → 调 `guardAction(onProceed)`。
- `export type SkillDetailPageHandle`(供 ref 类型)。

### 2. `src/components/skill/SkillManagerPage.tsx`
- `import { useRef } from 'react'`、`import type { SkillDetailPageHandle }`。
- 新增 `const detailRef = useRef<SkillDetailPageHandle>(null);`,传给 `<SkillDetailPage ref={detailRef} ... />`。
- 新增 `handleSelectSection(section: AppSection)`:
  ```ts
  const handleSelectSection = (section: AppSection) => {
    if (selectedSkillId && detailRef.current) {
      detailRef.current.requestNavigateAway(() => setAppSection(section));
    } else {
      setAppSection(section);
    }
  };
  ```
- `<Sidebar onSelectSection={handleSelectSection} onSkillSettings={...} />`。
- `setAppSection` 从 `useUIStore` 解构。

### 3. `src/components/layout/Sidebar.tsx`
- `SidebarProps` 新增 `onSelectSection?: (section: AppSection) => void`。
- `const selectSection = onSelectSection ?? setAppSection;`
- 两处 `SectionButton` 的 `onSelect` 从 `setAppSection` 改为 `selectSection`。
- 注意:Sidebar 在 PromptManagerPage 不传该 prop → 回落 `setAppSection`(无守卫,本次需求)。

### 4. 测试
- `src/components/layout/Sidebar.test.tsx`:加用例——传 `onSelectSection` 时点击 SectionButton 调用它而非 `setAppSection`(确保覆盖默认行为生效)。
- 由于 `SkillDetailPage` 无现成测试文件,本次不为它新建测试文件(避免引入需 mock SkillService 的复杂测试);核心守卫逻辑由现有 `selectEntry`/`back` 路径已隐式覆盖。新增 `guardAction` 是纯重抽取,行为等价。
