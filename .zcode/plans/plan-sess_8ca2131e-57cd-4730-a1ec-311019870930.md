# Skill 编辑页面优化方案

## 问题诊断（需求 3 的根因）

新建文件夹/文件等功能无法使用的**根因已确认**：`SkillDetailPage.tsx` 中 5 个文件操作（新建文件夹/文件、上传、重命名、删除）和未保存确认/同步提示，全部依赖 **`window.prompt` / `window.confirm` / `window.alert`**。但 Tauri 2 的系统 webview（macOS 的 WKWebView、Windows 的 WebView2）**不实现同步的 `window.prompt()`** —— 调用直接返回 `null`，导致：

- `createFolder`/`createFile`/`renameSelected`：`window.prompt(...)` → `null` → `.trim()` → 提前 `return`（静默失效，这就是"新建文件夹/文件无法使用"）
- `window.confirm` 在 Tauri 中恒返回 `true`，使删除/未保存确认被静默跳过（更隐蔽的 bug）
- `window.alert`（同步失败提示）不渲染

**修复方案**：用应用内 `Modal` 输入框（复用现有 `@/components/common/Modal`，仿 `SkillCreateModal` 样式）替换所有原生对话框调用。结合需求 1、2 的重构一并完成。

## 实施步骤

### 1. 新建「名称输入」Modal 组件 — `src/components/skill/SkillNamePromptModal.tsx`
复用现有 `Modal` 组件，用于「新建文件夹 / 新建文件 / 重命名」三处文本输入。Props：
```ts
{ isOpen, onClose, onSubmit: (name: string) => void,
  title: string, label: string, placeholder?: string,
  initialValue?: string, confirmLabel: string, isSubmitting?: boolean }
```
- `isOpen` 变化时清空/回填输入；回车提交、ESC/点遮罩取消（`Modal` 已内置）
- 输入框样式沿用 `SkillCreateModal`：`h-10 w-full rounded-lg border border-border bg-bg px-3 ... focus:border-accent`
- trim 后非空才允许提交（按钮 disabled）
- 添加到 `src/components/skill/index.ts` barrel

### 2. 新建「确认」Modal — `src/components/skill/SkillConfirmModal.tsx`
替代 `window.confirm`（删除确认、未保存放弃确认）。Props：
```ts
{ isOpen, onClose, onConfirm: () => void, title: string,
  message: string, confirmLabel: string, danger?: boolean, isSubmitting?: boolean }
```
- 样式仿 `SkillDeleteModal` 的 footer（`danger` 时用 `bg-red-600`）
- 添加到 barrel

### 3. 新建「右键菜单」组件 — `src/components/common/ContextMenu.tsx`
**codebase 中无任何 context-menu**，需新建。通过 `createPortal` 渲染到 `document.body`（仿 `ShareImageModal` 的 portal 模式，规避树容器的 `overflow:hidden`/transform）。API：
```ts
export interface MenuItem { key: string; label: string; icon?: string;
  danger?: boolean; disabled?: boolean; separatorBefore?: boolean }
export interface ContextMenuProps { open: boolean; x: number; y: number;
  items: MenuItem[]; onClose: () => void; onSelect: (key: string) => void }
```
- `position: fixed` 定位到点击坐标，靠近视口边缘时自动翻转（避免溢出）
- mousedown 落在菜单外 / ESC / 滚动 → 关闭（监听逻辑仿 `Modal.tsx` 的 escape 模式）
- 菜单项样式：`flex w-full items-center gap-2 px-3 py-2 text-sm hover:bg-surface-dim`，`danger` 用 `text-red-600`
- 加到 `src/components/common/index.ts` barrel

### 4. 重构 `SkillFileTree.tsx` — 展示根目录 + 折叠 + 右键
Props 扩展：
```ts
entries: SkillFileEntry[]; selectedPath: string | null;
collapsedPaths: Set<string>;          // 新增：外部受控折叠状态
skillName: string;                    // 新增：根节点标签（= skillId）
onToggle: (relativePath: string) => void;          // 折叠/展开
onSelect: (entry: SkillFileEntry | null) => void;  // null = 选中根
onContextMenu: (entry: SkillFileEntry | null, x: number, y: number) => void;  // 新增
```
关键改动：
- 顶层先渲染一个**根节点行**（图标 `folder_open`/`folder`，展开时显示子项），`paddingLeft` 起始深度从 0 调整为根节点
- 点击文件夹节点 → `onToggle`（**不再触发选中编辑**）；点击文件 → `onSelect`
- 文件夹/文件行折叠态图标用 `expand_more`（子项展开）/`chevron_right`（折叠），已在字体子集中
- 每个节点（含根）加 `onContextMenu` 调用 `onContextMenu(entry, e.clientX, e.clientY)` 并 `e.preventDefault()`
- 受控折叠状态由父组件持有（`SkillDetailPage`），便于右键操作后正确刷新展开

### 5. 重构 `SkillDetailPage.tsx` — 移除工具栏 + 接入新交互
- **删除**：顶部 5 个操作按钮（newFolder/newFile/upload/rename/delete），**仅保留**「返回」和「导出 ZIP」`DetailAction`（下载按钮移到右键菜单）
- **新增状态**：`collapsedPaths: Set<string>`、`menu: { entry, x, y } | null`、`namePrompt: { mode: 'folder'|'file'|'rename', target } | null`、`confirmState`、`pendingUploadDir`
- **折叠逻辑**：`toggle(path)` → 复制并切换 Set 中的成员；默认空 Set（全展开）
- **右键菜单项**（根据 `entry` 类型动态生成）：
  - **根节点 / 文件夹**：新建文件夹、新建文件、上传文件、粘贴/重命名（仅文件夹）、删除（仅非根非受保护文件夹）
  - **文件**：重命名、删除、下载（仅非受保护；`SKILL.md` 仅显示下载）
- **操作目标上下文**：将原 `childPath(selected, name)` 改为 `childPath(menuEntry ?? selected, name)` —— 右键哪个节点就在哪个目录下新建；点根节点的右键 = 根目录
- **新建/重命名流程**：打开 `SkillNamePromptModal` → `onSubmit` → 调原 `SkillService.createDirectory/createTextFile/renameEntry`（路径计算逻辑不变）→ 关闭弹窗 + `refresh`
- **删除流程**：打开 `SkillConfirmModal`（danger）→ 确认 → `deleteEntry`
- **上传流程**：右键"上传文件" → `open()` 选文件 → 直接 `uploadFile`（无需文本输入），目标目录来自右键节点
- **下载流程**：保留 `SkillService.downloadFile`，从右键菜单触发
- **未保存确认**：`selectEntry`/`back` 中的 `window.confirm` → 改为 `SkillConfirmModal`（异步流，需在 `selectEntry` 里改为"如脏则弹窗，确认后再切换"，用 `useRef` 存挂起的 entry）
- **同步失败提示**：`window.alert` → 改用一个轻量内联 `error` 横幅（`runMutation` 里 `syncErrors.length > 0` 时 `setError(true)` 并附带 `t.skills.syncPartialFailure` 文案，复用现有 error 横幅机制），或简单用 `SkillConfirmModal` 单按钮。**优先用内联横幅**（已有 error 横幅 UI）

### 6. i18n 新增条目（`src/i18n/messages.ts` 四种语言同步）
在 `skills` 块下新增（每种语言 zh-CN/zh-TW/en-US/ja-JP 都加）：
- `folderName: '文件夹名称'` / `fileName: '文件名称'` / `newFolderTitle: '新建文件夹'` / `newFileTitle: '新建文件'` / `renameTitle: '重命名'`
- `confirm: '确定'`（通用确认按钮）/ `namePlaceholder: '请输入名称'`
- `deleteEntryConfirm: (name) => \`确定删除"${name}"吗？\`` / `deleteEntryNote: '此操作不可撤销。'`
- `uploadSuccess: '上传成功'`（可选，若用横幅）
- 保留现有 `newFolder/newFile/uploadFile/rename/delete/download` 作为菜单项 label
- 保留 `unsavedChanges`，删除 confirm 调用改走 modal

### 7. 不需要重新生成字体
所需图标（`folder`/`folder_open`/`expand_more`/`chevron_right`/`create_new_folder`/`note_add`/`upload_file`/`drive_file_rename_outline`/`delete`/`download`/`lock`/`markdown`/`description`/`draft`）**已全部在 `scripts/icon-glyphs.txt` 中**，无需运行子集化脚本。若新增了菜单专用图标（如 `content_cut`/`content_paste`）才需要重跑——当前设计不引入新图标。

## 验证步骤
1. `npm run type-check` — TS 类型通过
2. `npm run lint` — ESLint 通过
3. `npm run test` — 现有测试不回归（不新增后端逻辑，后端 `commands.rs`/`files.rs`/`paths.rs` 不改）
4. `npm run build` — 构建通过
5. 手动验证（Tauri 桌面端）：
   - 左侧显示 skill 根目录节点，可折叠/展开
   - 右键文件夹 → 新建文件夹/文件，弹窗输入名称后**真正创建**（修复 bug）
   - 右键文件 → 重命名/删除，弹窗确认后生效
   - 右键 → 上传文件，选择后上传到对应目录
   - `SKILL.md` 右键只有下载，重命名/删除禁用
   - 顶部仅保留返回 + 导出
   - 切换文件时有未保存修改 → 弹应用内确认框

## 影响范围
- **新增 4 文件**：`SkillNamePromptModal.tsx`、`SkillConfirmModal.tsx`、`common/ContextMenu.tsx`，barrel 更新
- **重构 2 文件**：`SkillFileTree.tsx`、`SkillDetailPage.tsx`
- **i18n 1 文件**：`messages.ts`（四语言块各加约 8 个 key）
- **不改**：`skillService.ts`、`types/skill.ts`、所有后端 Rust 代码（`files.rs`/`paths.rs`/`commands.rs` 的未提交改动与本任务无关，保持原样）
- **不依赖**新字体子集、新后端命令

## 风险与权衡
- `selectEntry` 改异步未保存确认会让该函数复杂度上升：用 `useRef<SkillFileEntry | null>` 存挂起目标，确认回调里再执行读取。可控。
- 受控折叠状态 `Set<string>` 体积小，刷新 `loadTree` 后不重置，体验一致。
- 右键菜单 `createPortal` 到 `document.body`，需注意 Tauri SSR 守卫（`typeof document !== 'undefined'`），与 `ShareImageModal` 一致。
