# Agent 工具拖拽排序

## 决策已确认
- **排序持久化**：后端（Rust `SkillManagerSettings` 新增 `tool_order: Vec<String>`）
- **排序范围**：全局统一顺序（builtin + custom 共用一个顺序）
- **拖拽实现**：`@dnd-kit/core` + `@dnd-kit/sortable`

## 一、数据流设计（核心）

排序的真值源在 Rust `SkillManagerSettings.tool_order`（tool id 数组）。

**排序应用点 = `detect_tools` 末尾**：builtin（按 registry 顺序）+ custom（按 Vec 顺序）拼接后，根据 `tool_order` 对结果稳定排序：`tool_order` 中出现的 id 按其位置排，未出现的（新增工具/迁移老用户）追加到末尾（保持原相对顺序）。这样**所有下游消费点（store、Sidebar、SkillCard、SkillSettingsModal）自动获得正确顺序**，无需在各组件重复排序逻辑。

## 二、Rust 后端改动

### 2.1 models.rs — 新增 `tool_order` 字段
```rust
pub struct SkillManagerSettings {
    ... 现有字段 ...
    #[serde(default)]
    pub tool_order: Vec<String>,   // 新增：用户自定义的工具 id 顺序
}
```
`Default` 补 `tool_order: Vec::new()`（空 = 用 registry/custom 原序）。

### 2.2 config.rs — 解析新字段
`RawSettings` 增加 `#[serde(default)] tool_order: Vec<String>`，`parse_settings` 直接透传。旧文件无此字段时为空数组（向后兼容，无需 schema 迁移）。补一个往返测试。

### 2.3 detector.rs — 末尾应用排序
在 `detect_tools` 返回前插入排序逻辑：
```rust
apply_tool_order(&mut tools, &settings.tool_order);
```
新增 helper：
```rust
fn apply_tool_order(tools: &mut Vec<AgentTool>, order: &[String]) {
    if order.is_empty() { return; }  // 空则保持原序（默认行为）
    let position: HashMap<&str, usize> = order.iter().map(|id| id.as_str()).enumerate().collect();
    tools.sort_by_key(|tool| position.get(tool.id.as_str()).copied().unwrap_or(usize::MAX));
}
```
未出现在 `tool_order` 的工具排到末尾，且彼此保持原相对顺序（`sort_by_key` 稳定排序）。补测试验证排序与回退行为。

### 2.4 commands.rs — 新增 IPC `skill_reorder_tools`
```rust
#[tauri::command]
pub fn skill_reorder_tools(tool_order: Vec<String>) -> Result<SkillScanResponse, SkillManagerError>
```
内部 `reorder_tools_at(home, exe_dirs, tool_order)`：
- 读 settings，**校验 tool_order 是当前所有工具 id 的排列**（长度一致 + 集合相同，否则报 `skill_tool_order_invalid`，避免写入残缺/多余 id）
- 写 `settings.tool_order`，save，scan 返回最新快照

### 2.5 lib.rs — 注册新命令
`invoke_handler` 增加 `skills::commands::skill_reorder_tools`。

这是唯一需要拖拽交互的地方。改造工具列表：

## 四、边界与一致性保证

1. **新增/删除自定义工具**：`add_custom_tool` 返回的 scan 中，新工具按 detect_tools 逻辑追加到末尾（tool_order 未含它 → 排末尾），顺序自动正确。删除工具时 `reorder` 不需联动——tool_order 中残留的已删 id 在下次 `reorder` 校验时会被视为无效... **需处理**：`remove_custom_tool` 同时从 `tool_order` 移除该 id，避免校验失败。
2. **未安装/已禁用工具**：仍参与排序（它们在 settings 列表全量显示，可拖动），Sidebar/SkillCard 过滤后顺序继承。
3. **空 tool_order**：首次使用（老用户/未排序过）为空数组，detect_tools 保持 registry 原序，行为与现状一致。
4. **校验**：`reorder_tools` 必须校验 tool_order 包含当前所有工具 id（builtin 全部 + custom 全部），拒绝残缺/多余，防止数据不一致。

## 六、风险点
- `@dnd-kit` 与 React 18.3.1 兼容（官方支持 React 16.8+）
- `drag_indicator` 图标可能未在字体子集 → 检查并按需重新生成
- remove_custom_tool 必须联动清理 tool_order，否则 reorder 校验失败
