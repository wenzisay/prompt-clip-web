## 目标

在 skill 详情页为 `.html` / `.htm` 文件增加「编辑 / 预览」切换，预览用 `<iframe sandbox srcDoc>` 做纯静态渲染（脚本不执行、与父应用隔离），与现有 MD 预览体验对齐。

## 现状回顾

- `SkillFileEditor.tsx` 的 Edit/Preview 切换当前仅对 `entry.isMarkdown` 为 true 的文件显示（`:56`、`:97`）。
- MD 预览：`renderMarkdown`(marked) → `dangerouslySetInnerHTML` 注入 prose 容器（`:117-133`）。
- `.html` 后端归为 `isText=true` 但 `isMarkdown=false`，所以只有纯文本 textarea，没有预览。
- `t.skills.edit` / `t.skills.preview` 四语言已存在，无需新增 i18n。

## 方案

HTML 不能复用 MD 的 prose 注入路径（自带 `<style>` 会污染全局样式、`<script>` 会跑在 app 上下文），改用 iframe sandbox 隔离。按已确认的决策：**sandbox="" 禁脚本 + srcDoc 喂内容**。

### 改动 1：`src/components/skill/SkillFileEditor.tsx`

1. 顶部新增模块级 helper（仅前端按扩展名判定，避免改 Rust 后端 + Tauri 重新编译，web/tauri 通用）：

   ```ts
   const isHtmlFileName = (name: string): boolean => {
     const lower = name.toLowerCase();
     return lower.endsWith('.html') || lower.endsWith('.htm');
   };
   ```

2. 组件内派生：`const isHtml = isHtmlFileName(entry.name);`

3. 切换按钮条件 `:56`：`entry.isMarkdown` → `entry.isMarkdown || isHtml`（复用现有 Edit/Preview 按钮与 aria 文案，HTML 文件也会显示这组切换）。

4. 预览区 `:97`：分支渲染——
   - `preview && isHtml` → 新组件 `<SkillHtmlPreview value={content} name={entry.name} />`
   - `preview && entry.isMarkdown` → 现有 `<SkillMarkdownPreview />`
   - 否则 → 现有 `<textarea>`

5. 新增 `SkillHtmlPreview` 组件（与 `SkillMarkdownPreview` 并列）：

   ```tsx
   function SkillHtmlPreview({ value, name }: { value: string; name: string }) {
     return (
       <iframe
         data-testid="html-preview"
         title={name}
         srcDoc={value}
         sandbox=""
         className="min-h-0 w-full flex-1 border-0 bg-white"
       />
     );
   }
   ```
   - `sandbox=""`：禁脚本、禁表单、禁同源访问 → 纯静态结构+样式预览。
   - `srcDoc={value}`：直接用编辑中的 `content`，切换到预览即看到当前内容（与 MD 预览行为一致；预览模式下 textarea 隐藏，内容不再变化）。
   - `title` 提供无障碍标签；`bg-white` 保证空页面可见。

### 改动 2：`src/components/skill/SkillFileEditor.test.tsx`

新增一个测试用例（HTML 条目 `isText:true, isMarkdown:false`）：
- 显示 Edit/Preview 切换组。
- 点 Preview 后出现 `data-testid="html-preview"` 的 iframe，其 `sandbox` 属性为空串、`srcDoc` 为文件内容、`title` 为文件名。
- 点 Edit 回到 textarea。

> 注：jsdom 不会真正解析 iframe 内文档，故只断言 iframe 元素的属性，不断言 iframe 内部 DOM。

## 不改的部分

- 后端 Rust（`files.rs` 的 `is_text_path`/`is_markdown_path`、`SkillFileEntry`）：不动。HTML 已是 `isText`，能正常读取为字符串。
- 类型 `SkillTextFile` / `SkillFileEntry`：不动。
- i18n：不动（复用 `t.skills.edit` / `t.skills.preview`）。
- MD 预览路径：不动。
